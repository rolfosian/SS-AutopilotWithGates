Version 0.0.3b

- Mitigated random crash caused by null mapLocation
- Fixed rare case of map course arrows not rendering on intel tab hyperspace map if player opens intel tab with interaction dialog open after user has selected an option that shows a smaller map >2 times in a row
- Added changelog, version files

Version 0.0.3c

- Added mouse scrolling for campaign ability bar with mouse over ability bar (Disabled by default, enable via LunaSettings or settings.json if lunalib isn't installed/enabled)
- Fixed bug introduced with 0.0.3b where the course arrows would stop rendering on the intel map if the tab was opened again when it was already open

Version 0.0.4

- Added console command "AddGateAtPlayerLoc" which spawns an inactive gate at the player's location (It doesn't orbit anything)
- Added console command "ScanAllGates" which scans all gates in the sector

- Changed map handling under the hood, improved course arrows movement on maps
- Fixed crash that could occur if the game was launched with a different jre version than the one the game ships with
- Fixed crash that could occur when LunaLib wasn't enabled
- Fixed course arrows not rendering on the hyperspace map of the planet tab of the intel core tab
- Fixed autopilot trying to use gates in systems with no viable entry point for entry gates, if the player is outside that location
- Fixed "go dark" ability disabling the autopilot with gates ability
- Fixed potential for rare silent concurrent modification exception on gate iterator thread which would have resulted in the autopilot missing gates that were scanned or added during gameplay until reload

Version 0.0.5

- Added extra dialog prompt to confirm transponder status for jump when transponder is off and target gate system is populated similar to vanilla jump points behavior
- Fixed bug with rare exception on gate iterator thread which could result in the autopilot missing gates that were scanned or added during gameplay until reload

Version 0.0.6

- Made it so autopilot doesn't resume automated course after saving the game if player is manually navigating while having a course set
- Stopped top middle "course laid in for x" messages showing on save

Version 0.0.6a

- Made it so autopilot doesn't resume automated course after saving the game if player is manually navigating while having a course set to a target **in system**

Version 0.0.6b

- Fixed bug introduced with last patch that made it so autopilot was overriding the interaction target if the player fleet was following a direct command when game saved

Version 0.1.3

- Added blacklist for player to add gates to that they want the autopilot to ignore - accessed via hotkey with mouseover tooltip showing on ability bar
    There is a lunalib or settings.json config option to change the hotkey for this if desired

- Integrated the Ashes of the Domain - Vaults of Knowledge Bifrost gate network.
    Includes backwards compatibility for pre-5.x versions.
    If Bifrost gates are being used by the autopilot then the circles for the gate course on the hyperspace map will be colored cyan

- Added settings option for the autopilot to prefer Bifrost Gates every time if the connection is off cooldown and they share the same entry/exit systems as the resolved route for normal gates
- Added LunaSettingsListener, settings with lunalib enabled will now take immediately if saved during campaign gameplay and won't have to wait for save reload

- Moved ability tooltip strings to settings.json for localization support (Can also be assigned programmatically by setting the appropriate static fields in data.scripts.autopilotwithgates.AutoPilotGatesAbility)
- Polished ability tooltip, added some related codex entries

Version 0.1.3a

- Fixed crash on game save when ability isnt unlocked

Version 0.1.4

- Reworked gate blacklist dialog. Gates in systems not shown on the hyperspace map can now be picked via a different sub-dialog
- Fixed regression crash on At the gates quest completion
